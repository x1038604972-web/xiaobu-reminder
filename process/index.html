CHAPTER 00 · 起点

先让它跑起来，再谈好不好用

第一天做出来的东西很朴素：一个列表、一个输入框、三个 tab。但有三条硬约束从第一天就定死了，后面所有的改动都在这三条里做。

1
全部代码在一个 index.html 里HTML + style + script，不拆文件、不引外部库。改完直接丢上去就能跑。
2
数据只存在 localStoragekey 是 qingji_tasks_v1，不能改——改了用户的事就全没了。
3
视觉只用一套变量纸质米色 + 松绿，颜色写在 :root 里，改动必须沿用，不许新造配色。
✓
好处是：每次改完都能立刻在手机上试；坏处是：一个文件到后期已经 25 万字符，改错一行就全白。
CHAPTER 01 · 方法

我是怎么"指挥"AI 写这个 App 的

不是"帮我把这个 App 做出来"，而是把它拆成 13 条可以验收的指令：先说清 bug 的表现，再说要改成什么样，最后写验收标准。下面这段是每次对话开头都要粘的总控指令。

总控指令 · 每次对话开头
你是我的前端开发搭档。项目是「小步」——一个单文件 HTML 的提醒 App。

技术约束（必须遵守）
1. 全部代码在 index.html 里，不要拆文件、不要引入外部库或 CDN。
2. 数据存在 localStorage，key 是 qingji_tasks_v1，不能改。
3. 视觉是「纸质米色 + 松绿」，变量在 :root，改动必须沿用。
4. 外层 .phone 是 390×844 手机壳，不要拆掉。

工作方式
· 每次只做我要求的那一处改动，告诉我改了哪几行、怎么验证、有没有副作用。
· 改完必须自查：加一条 → 勾选 → 删除 → 切三个 tab，都不能报错。
· 输出只贴改动涉及的那几段，不要整份重发。

为什么每条都要写"验收"？

比如指令 1：「造一条 1 小时前到点的任务，刷新 → 必须弹出来；连续刷新 3 次 → 只弹一次；3 条逾期 → 只弹 1 个汇总窗」。 写不出验收标准，说明我还没想清楚要什么——这时候让 AI 动手，只会得到一个"看起来改了"的版本。

CHAPTER 02 · 版本

37 个版本，是"退"出来的

每次让 AI 动手之前，先把 index.html 复制一份，文件名写清这次要改什么。改坏了就退回去。 下面每一条都是一次改动前留下的存档，条形的长度是当时的文件体积。

CHAPTER 03 · 反馈

别人一用，问题才浮出来

两组访谈、12 条吐槽。真正有用的不是"他说了什么"，而是把吐槽翻译成病因——同一个病因可能对应好几条抱怨。

最扎心的一条

「帧率低了。」——不是手机差，是我给液态玻璃主题上了大面积 backdrop-filter，还叠了完成粒子特效。 这条反馈逼着我加了「性能优先」开关，也让我第一次意识到：好看是要付性能税的。

CHAPTER 05 · 形象

给它一张脸

助手叫「小步」，但一开始它只是气泡旁边一个「布」字。后来画了三视图：围巾上的对勾是 App 的完成符号，围巾的绿就是品牌色。这样它看起来本来就属于这个产品。

① 抠图从三视图里泛洪去底 + 只留最大连通块，顺手清掉脚下阴影和标签文字
② 圆形头像按围巾上缘裁出头肩，套圆形蒙版，24px 小气泡里也认得出
③ 变成图标绿底圆角 + 全身，做成桌面图标、favicon、通知图标
CHAPTER 06 · 对话

从"能记"到"会聊"

小布不是把聊天框贴在 App 上，它得能真的改数据。所以做成三层：本地先判断你要干什么，判不出来才问大模型，最后由同一套执行器落地——模型再聪明也改不坏数据。

① 本地意图引擎关键词 + 正则识别「记 / 查 / 改 / 完成 / 删除 / 设置」，复用 App 自己的时间解析，离线可用、零成本
② 大模型（可选）DeepSeek / Kimi / 通义，浏览器直连；只负责把绕的说法翻成动作 JSON，Key 存在本机
③ 执行器模型和本地共用一个执行器：真的写 tasks、重渲染、弹 toast、给「撤销」；不确定就问，不乱改
1
「明天9点提醒我交作业」 → 真写入列表，卡片给「改时间 / 撤销」
2
「提醒我背单词」 → 缺时间会反问，补一句「明天7点」就落库（多轮槽位）
3
「每周三四早上喝牛奶」 → 解析成 weekMask，列表显示「每周 三、四」
4
「删掉牛奶」（有两条相似）→ 追问「要动哪一条」+ 序号胶囊
5
「我明天忙不忙」 → 报明天的量；「打开适老化」 → 直接改设置
CHAPTER 07 · 通知

提醒要能追到人

提醒只在 App 里弹，等于没提醒。但网页画不到别的 App 上面——能做的是系统通知：它会从任何界面顶部滑下来。

1
安卓必须走 Service Worker：页面里 new Notification() 会直接抛错，之前一直是静默失败的
2
通知里就能处理：「完成」「推迟 10 分钟」两个动作，重要档常驻不消失 + 长震动
3
点完能回写：App 没开着也能通过 URL 参数把这条标记完成 / 推迟
4
边界也说清楚：App 被系统杀掉后网页醒不过来，要真闹钟级别得上原生封装或服务器推送

它不是被"生成"出来的，是被一条条改出来的

37 个备份、13 条指令、12 条吐槽、7 次重做——这条路上最有用的不是 AI 有多强， 而是每一步都能退回去、都能验收、都能在手机上说给自己听。
